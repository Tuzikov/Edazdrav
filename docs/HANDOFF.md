## Что это за проект
Android-приложение подсчёта калорий по фото (React Native / Expo).
Бриф — [PROJECT_SPEC.md](../PROJECT_SPEC.md). Название и иконка — «Едазавр»
(T-Rex из еды).

## Текущее состояние — MVP полностью рабочий
- Вкладки Сегодня / История / Профиль, flow добавления блюда
  (фото / галерея / вручную), экран деталей и редактирования уже
  сохранённых приёмов.
- Реальный бэкенд: Supabase Edge Functions (`recognize-meal`,
  `lookup-nutrients`, `lookup-ingredient`) — дёргают Gemini (распознавание
  фото + перевод названий) и USDA FoodData Central (нутриенты). Gemini —
  платный тир (был лимит free tier 20 запросов/день, пользователь включил
  биллинг).
- Калькулятор целей (формула Миффлина-Сан Жеора) в Профиле, плюс ручной
  ввод целей.
- История: факт/план по калориям и выбранному нутриенту в шапке каждого
  дня; счётчик «N дней в режиме 👍» (геймификация, считает подряд идущие
  календарные дни без превышения плана по калориям).
- Кольцо калорий на «Сегодня» краснеет при перерасходе.
- Android: edge-to-edge поддержан (`react-native-edge-to-edge` +
  `useSafeAreaInsets`), иконка приложения и adaptive icon — с отступами под
  безопасную зону маски, без обрезки.
- Иконка вкладки «Профиль» — контурный T-Rex (`assets/images/profile-tab-icon*.png`,
  тонируется через `tintColor`), заменил стандартный `person-outline`.
- **Редизайн «Сочный»** — тёплая оранжевая палитра вместо чёрно-белой,
  токены в `src/constants/theme.ts` (`accent`, `accentButton`, `danger`,
  `nutrientProtein/Fat/Carbs/Fiber`, light+dark). Применено по всему
  приложению, не только на исходных 3 экранах макета.
- **Синхронизация с Health Connect** (Android-only, одностороннaя —
  приложение только пишет, ничего не читает обратно) — тумблер в Профиле,
  выключен по умолчанию. При включении запрашивает разрешение
  `android.permission.health.WRITE_NUTRITION`, при сохранении/редактировании
  приёма пищи пишет `NutritionRecord` (калории+БЖУК) в Health Connect.
  **Подтверждено пользователем работающим на реальном устройстве
  (Android 16, Samsung)** после нескольких раундов отладки — см. «На
  заметку» ниже, там все грабли расписаны на будущее.
- **Переключатель темы** (Системная/Светлая/Тёмная) в Профиле — раньше
  тема жёстко следовала за системной, теперь можно переопределить.
  `ThemePreferenceProvider` + `useResolvedColorScheme()`
  (`src/context/theme-preference-context.tsx`,
  `src/hooks/use-resolved-color-scheme.ts`) — выбор сохраняется в
  AsyncStorage, применяется везде (контент, таб-бар, статус-бар через
  `SystemBars` из `react-native-edge-to-edge`).
- Последний собранный и подтверждённый пользователем на реальном устройстве
  APK — коммит `1069457` (все три фичи выше + рабочий Health Connect).
  Ссылки на артефакты EAS Build не вечные — если ссылка из истории чата уже
  не работает, просто пересобрать:
  `npx eas-cli build -p android --profile preview --non-interactive`.

## На заметку (грабли, на которые уже наступали)
- **Health Connect — целая сага граблей, если будешь трогать эту часть:**
  1. Конфиг-плагин `react-native-health-connect` регистрирует только
     экран-обоснование разрешений в манифесте — сам
     `<uses-permission android:name="android.permission.health.WRITE_NUTRITION"/>`
     нужно объявлять вручную через `android.permissions` в `app.json` (как
     `RECORD_AUDIO`). Без этого Android вообще не показывает системный
     диалог разрешения.
  2. В самой библиотеке (`node_modules/react-native-health-connect`, метод
     `requestPermission` в `HealthConnectManager.kt`) нет `try/catch` вокруг
     нативного вызова — единственный метод в файле без него (у всех
     остальных, `insertRecords`/`readRecords`/etc., он есть). Любая нативная
     ошибка там просто проглатывалась вместо того, чтобы отклонить promise.
     Пропатчено через `patch-package` (`patches/react-native-health-connect+4.1.3.patch`,
     см. `postinstall` в `package.json`) — патч добавляет `try/catch` и
     теперь реальные ошибки долетают до JS.
  3. Финальная причина, почему разрешение выдавалось, но данные не
     записывались: `NutritionRecord` — это `IntervalRecord`, Health Connect
     требует `startTime < endTime` строго. Приём пищи в модели приложения —
     мгновенное событие (`meal.createdAt` для обоих полей), поэтому все
     записи падали с `startTime must be before endTime`. Исправлено в
     `src/lib/health-connect.ts` — `endTime = startTime + 1 минута`.
  4. `src/lib/health-connect.ts` хранит последнюю ошибку синхронизации в
     AsyncStorage (`getLastSyncError`) и показывает её в Профиле под
     тумблером — полезно для будущей отладки, специально не убирал после
     фикса.
  5. Подтверждено на реальном устройстве (Android 16, Samsung — приложение
     показывается в Health Connect как «Приложение партнёр», данные видны в
     «Данные приложения»).
- USDA FoodData Central API периодически отдаёт 400 без видимой причины
  (не связано с частотой запросов) — в `supabase/functions/_shared/usda.ts`
  уже есть ретрай (до 4 попыток), но полностью исключить нельзя.
- Общий фолбэк по нутриентам (120 ккал / 6Б / 5Ж / 12У / 1.5 клетч. на
  100г, см. `GENERIC_FALLBACK` там же) срабатывает, если USDA вообще не
  находит совпадение — может давать неточные цифры для редких/специфичных
  продуктов.
- Промпт для Gemini явно разделяет "твёрдая еда" (можно добавлять
  raw/grilled/boiled) и "напитки/жидкости" (нельзя добавлять raw/cooked) —
  раньше "вода, raw" уводила поиск USDA в сторону не той еды.
- Фото в истории хранятся как временная cache-ссылка от `expo-image-picker`
  (не копируются в постоянное хранилище) — при очистке кэша Android
  картинка может перестать открываться, но данные о калориях не пострадают.
  Обсуждали с пользователем, договорились пока не чинить.
- Локальный `~/.npm` кэш на машине пользователя один раз был испорчен
  root-owned файлами — если `npm install` внезапно падает с `EACCES`:
  `sudo chown -R $(whoami):staff ~/.npm`.
- На macOS для растровых операций с иконками используется `sips` (встроен)
  и Pillow (`pip3 install Pillow`) — оба уже проверялись рабочими на этой
  машине.

задеплоенное, список выше — это просто хвосты на будущее, не срочно.
